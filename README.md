# OBOU Automations — marketing site

The marketing site for OBOU Automations (obouautomations.com): seven pages
built on TanStack Start, React, TypeScript and Tailwind, rendered on the server
and hydrated in the browser.

It replaces the hand-built static HTML site that lived here previously (still in
git history before the TanStack rewrite). The design is unchanged — the same
Swiss/International-typographic system: two grounds, two accents, zero radius,
self-hosted Archivo.

## Development

Needs Node.js and a package manager. The lockfile is `bun.lock`, so Bun is the
path of least resistance.

```sh
bun install
bun run dev        # http://localhost:5173
bun run build      # production build
bun run preview    # serve the build
bun run lint       # eslint
bun run format     # prettier
```

`npm` works too — it will resolve from `package.json` and write its own lockfile,
which you probably don't want to commit alongside `bun.lock`.

## Layout

```
src/routes/            file-based routes: /, about, solutions, work, tools,
                       how-to-start, contact — plus __root.tsx (html shell,
                       head tags, 404 and error boundaries)
src/components/        site.tsx holds the shared page furniture (PageFrame,
                       PageHero, Flow, FinalCTA…); ui/ is shadcn/ui
src/lib/site-content.ts   copy and data that more than one route renders,
                          including BOOKING_URL
src/lib/security-headers.ts   the response header policy (see below)
src/styles.css         Tailwind entry, design tokens, page composition
src/server.ts          SSR entry: error handling plus security headers
src/start.ts           request middleware (error boundary, CSRF)
src/routeTree.gen.ts   generated by TanStack Router — do not edit
public/                favicon, logo, robots.txt, Archivo woff2
_headers               Netlify / Cloudflare Pages response headers
security-headers/      the same policy for Vercel, nginx, Apache + POLICY.txt
```

## Security headers

`security-headers/POLICY.txt` is the canonical policy and explains every
directive. The short version: the SSR handler in `src/server.ts` stamps the
policy onto every response it renders, so it travels with the app to any host.
The four config files cover static assets served straight off a CDN.

Five files express one policy. Change one, change all five — POLICY.txt says
which.

## Contact

The Google Calendar booking link is the site's primary contact destination:

```
https://calendar.app.google/BovBGfzf4FPaK53v7
```

It lives in `src/lib/site-content.ts` as `BOOKING_URL` — one constant, imported
everywhere it's used. That is the single thing to change to swap in a different
booking tool.

**The two forms do not submit anywhere.** The contact form (`src/routes/contact.tsx`)
and the opportunity finder (`src/components/opportunity-finder.tsx`) both call
`preventDefault()` and stop. Anyone filling one in gets no response and you get
no lead. Wiring them up means adding a server function or a form endpoint, and
widening `form-action` in all five header files at the same time.

## Deploying

The build targets Cloudflare Workers by default (Nitro, via
`@lovable.dev/vite-tanstack-config`). `bun run build` produces the server bundle
and the static assets; deploy with Wrangler or connect the repo to Cloudflare.

Other hosts work — the SSR handler is a standard `fetch` export — but need the
matching Nitro preset and the matching file from `security-headers/`.

After any deploy, check the headers actually arrived:

```sh
curl -sI https://obouautomations.com | grep -i -E 'content-security|strict-transport|x-frame'
```

## Lovable

This project round-trips with [Lovable](https://lovable.dev): edits made there
are committed to this repo, and pushes here sync back into the editor.
`.lovable/` and `AGENTS.md` belong to that integration.

One consequence worth knowing: the tool logos on the home page are imported from
`src/assets/tool-logos/*.asset.json`, and each file's `url` is a Lovable asset
path (`/__l5e/assets-v1/…`). Confirm they render in a local production build
before trusting them in production — if they 404 outside the editor, the fix is
to move those SVGs into `public/assets/` and import them by path.
